## D1 插件名「灵犀 Lingxi」（2026，哲拍板）

- 备选：Qwen 库伴/Vault Butler、QwenVault 智库
- 理由：心有灵犀一点通，贴合「理解笔记」的产品气质；中英双语名都有辨识度
- 实现：manifest id = `lingxi`，显示名「灵犀 Lingxi」

## D2 默认接入学校网关 token.nau.edu.cn（OpenAI 兼容 /v1）

- 备选：本地 Ollama、留空自定义
- 理由：网关已实测在线；模型与上限已确认；哲已有账号
- 实测依据：
  - `GET https://token.nau.edu.cn/v1/models` 无 key 返回 **401**（网关在线，鉴权正常）
  - 模型与 max_total_tokens：qwen3.8-27b=**102400**、qwen3.6-35b-a3b-fp8=131072、
    qwen3.5-122b-a10b-fp8=150000；qwen3-embedding-8b 是**纯 embedding 模型**
    （在 /v1/messages 返回 404，不能当对话模型）
- 默认值：chatModel=`qwen3.8-27b`，embeddingModel=`qwen3-embedding-8b`，
  maxInputTokens=90000，maxOutputTokens=8192（102400 上限内留余量）

## D3 HTTP 传输必须用 requestUrl，不能用 fetch（2026，实测）

- 备选：fetch（可流式 SSE）、electron net.request（可流式但桌面限定）
- 实测依据：网关 401 响应头**不含 Access-Control-Allow-Origin** →
  Obsidian 渲染层 fetch 必被 CORS 拦截
- 决策：v0.1 全部走 `requestUrl`（Electron 层，免 CORS），**放弃流式输出**，
  对话为「思考中→整段呈现」；后续 Phase 再评估 electron net 流式（桌面-only 降级路径）

## D4 写权限：半自动（指定文件夹可自动整理，其余只建议）

- 备选：全建议+一键应用；全自动
- 理由：哲选择半自动。实现=设置里 `autoOrganizeFolders` 白名单，
  白名单内新笔记进自动打标签/双链流水线，其余一律建议列表
- 2026-10 落地形态：标签建议在白名单内 → `processFrontMatter` 直接写入；
  白名单外 → 芯片列表，点一下才写入。双链/重复检测一律只读不写。

## D5 功能清单由 2026 生态调研裁定（非拍脑袋）

调研对象与证据：
- **Smart Connections**（brianpetro/obsidian-smart-connections，官方 README）：
  核心是 Connections 视图（语义相关笔记+分数）、Lookup 语义搜索、拖拽成链、
  Send to Smart Context（一键复制 AI 就绪上下文）；Chat 已拆为独立 Smart Chat
- **Obsidian Copilot V4**（logancyang/obsidian-copilot，官方 README）：
  Agent/Projects/Skills/Commands、Quick Ask（选中即问、可继续/替换/插入/复制）、
  多会话标签、BYOK key 存 Keychain 不进 data.json
- **SystemSculpt 2026 横评**（systemsculpt.com/blog/best-obsidian-ai-plugins-2026）：
  四条真实标准=检索质量 / 控制与审批（suggest→review→apply 回路）/ 可重复工作流 / 安装摩擦；
  生态已分层：检索引擎 / 工作流操作器 / 自治 Agent
- **社区信号**：reddit 简要评测、obsidianstats local-ai 标签、awesome-obsidian-ai-tools

裁定结论（灵犀的差异化定位）：**不做 Agent 平台，做「回路型」笔记管家**——
检索强、引用可溯源、建议-审批-应用闭环、中英双语。具体功能见下轮交付的功能清单。

## D6 核心逻辑与 Obsidian 解耦

- 理由：Obsidian API 只能在 Electron 运行时用，绑死就无法 node 单测（工程规则 ③）
