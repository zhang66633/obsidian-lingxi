**本阶段抓到的两个真 bug（都靠测试暴露，非目测）**：
1. **切块静默截断**：超长区间的文本在 flush 时被提前截断再硬切分，导致内容丢失。
   修复：flush 不再截断，一律交给 hardSplit，并加「拼回原文」断言防回归。
2. **陈旧向量冒名命中**：文件改动后新 chunk 可能复用同 id（如 `a.md#0`），
   按 id 剪枝清不掉旧向量——旧内容的 embedding 会冒充新内容被检索到。
   修复：syncAll 先记录变更文件的旧 chunk id，剪枝时把这些 id 一并作废
   （`vaultIndexer.test.ts` 有专项回归）。

**API 变化记录**（已归入 02-踩坑记录.md）：typings 1.13.1 起
`Vault.cachedRead` 返回 `Promise<string>`（此前是同步 string）。VaultPort.readNote
因此改为异步，Obsidian 实现直接 return cachedRead 的 Promise——旧版同步返回
await 一下也安全。

**Headless 冒烟（TEMP/plugin-load-test.mjs，Node + obsidian mock）**：
把打包后的 main.js 当 CJS 加载，走完 `onload → 建侧边栏 UI → 切语言 → 空库检索`。
结果：✅ onload 正常（首跑提示 Notice 正常弹出）、视图注册正常、DOM 构建正常、
语言切换联动 RAG 引导句、空库不崩。过程中逼出 `retrieve` 空库短路的修复。
